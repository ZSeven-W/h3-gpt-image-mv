# 帧时间线、局部修复与导出

## 用同一条帧时间线

先在音乐里标出叙事段、重拍和动作落点，再定每个镜头的入点与出点。剪点用整数帧表示。镜头用半开区间 `[start, start + frames)`，从 0 开始且首尾相接。一个镜头可以从源片第 `source_start` 帧开始，最多取源片覆盖的范围。将四舍五入用于累计时间点，避免每镜单独按秒取整后全片漂移。

[15 秒示例](../assets/timeline.example.json) 使用三段，每段从 124 个源帧中取 120 帧。`first_frame`、`generate_frames`、`seed`、`motion` 和 `end_pose` 用于制作记录。脚本读取剪辑字段 `id`、`start`、`frames`、`source_start`、`source` 以及可选的 `soundtrack`。`source_start` 缺省时为 0。实际生成帧数从源文件校验。

## 按症状选修法

| 看到的问题 | 怎么确认 | 怎么修 |
| --- | --- | --- |
| 动作停顿、像丢帧 | 用 `ffprobe -show_packets` 看 PTS，再比较相邻画面。24 fps 约每 41.667 ms 出一帧，PTS 连续时仍需看片。 | 时间基不一致先按正确源帧率整理。若画面本身重复，回看源片和取帧范围。 |
| 两人走上台阶后又退回起点 | 比较前镜末帧和后镜首帧，找人物落脚、转身、手势、景别有没有重置。 | 去掉重复动作，改用动作完成后的镜头接续。需要换景别时，在动作已经成立的地方切入。 |
| 水面空镜长出人物，或手脚穿过道具 | 看首帧、生成片段和主体的空间关系。 | 调整首帧，缩短动作，只重生成该镜。雨水空镜可以收紧到水面微距，保留雨滴、灯光和涟漪。 |
| 两段姿态衔接，切点仍偏硬 | 逐帧核对手脚位置、运动方向和机位。 | 短补帧后放大复查手、裙边和前景，看到拉花或叠影就换剪点。 |

局部修复时，先锁定旧版时间区间。在相同区间放入新素材，使修复前后的音乐落点对齐。相似动作被剪了两次时，可删掉中间那次，用短桥接帧进入一条连续镜头，再在相同帧预算内调节后半段节奏。做公开版时单独检查标题、姓名、祝福语、字幕、文件名及元数据。

## 用脚本导出 1080p

将示例 JSON 复制到项目，并将 `source` 和 `soundtrack` 指向实际文件。相对路径以清单为基准。合片支持以下输入。

- 各镜头是 24 fps 的 1920 × 1080 或 1920 × 1088 本地 MP4，使用一致的色彩标签。1088 高度上下各裁 4 像素。
- 可选 `soundtrack` 是从零起播的 AAC 音轨，结束点和视频相差不到一帧。MP4 中只映射这条音轨。省略此字段可导出无声版。
- 字幕、补帧、变速和过渡先在剪辑器做成独立片段。不同画幅或色彩空间先整理成统一规格。

```bash
python3 /path/to/h3-gpt-image-mv/scripts/assemble.py timeline.json --check
python3 /path/to/h3-gpt-image-mv/scripts/assemble.py timeline.json --output mv.mp4
```

`--check` 校验源片尺寸、帧率、时间戳、可用帧数和音轨长度。`--output` 先把各镜头裁切、归零和编码，再拼接；使用 1/12288 的视频时间基，逐包校验时间戳按 512 递增，验证 AAC 数据保持一致，并完整解码新文件。输出目录需要留出源片规范化后的临时空间并支持硬链接。脚本把通过校验的文件原子写到新文件名，方便失败后重试。 [FFmpeg 裁切过滤器](https://ffmpeg.org/ffmpeg-filters.html#crop) · [拼接输入格式](https://ffmpeg.org/ffmpeg-formats.html#concat)

最后看完整成片，重点看片尾、重点动作与剪点。工具能核对编码和时间，角色是否滑步、牵手是否穿模需要看画面。
